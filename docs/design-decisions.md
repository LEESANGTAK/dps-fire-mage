## 2026-11-04 · 치명타 인지성: 붉은 치명타 전용음, 메테오 치명타 숫자·환호

- **문제:** 붉은 숫자(몰아치는 열기를 채우는 치명타)가 노란 치명타와 같은 소리라 귀로 구분되지 않았습니다(연속 2번째의 음높이 1.15배만 다름). 메테오 치명타는 숫자가 조금 클 뿐(2.65rem) 큰 사건답지 않았습니다.
- **결정:**
  - 붉은 치명타는 낮게 '훅' 붙는 점화음(`crit_heat`)으로 바꿉니다. 크기는 노란 치명타와 같게 두고 소리 결로만 구분합니다. 소리는 숫자 색이 아니라 열기 판정을 따릅니다(모션 줄이기로 숫자가 노랗게 나와도 열기는 차므로).
  - 메테오 치명타 숫자는 가장 크게(3.7rem × 1.5배) 화면 앞에서 내리꽂혀 찌그러진 뒤, 그 반동으로 위로 95px 솟구쳐(정점을 살짝 지나쳤다 돌아옴) 1.5초 여운을 둡니다(1부 4번 템포). 처음에는 제자리에서 튀기만 했는데, 사용자가 위로 팍 솟구치길 원해 바꿨습니다.
  - 착지 0.15초 뒤 남성 위주 관중 환호를 냅니다. 동시에 외치고 동시에 끊기는 후보는 어색해서, 하나둘 따라 붙고 흩어지며 잦아드는 3초짜리를 골랐습니다. 폭발보다 10dB 작게 겹칩니다.
  - **피로도:** 연소 중에는 메테오가 항상 치명타이고 쿨타임이 최소 4초라, 환호는 4초에 한 번까지만 냅니다(숫자 연출은 매번).
- **후보 선택:** 체크 페이지로 골랐습니다(1부 7번). 붉은 치명타 16개 중 1개, 환호 14개 중 2개.
- **관련 원칙:** 1부 2장(사건 규모별 반응 강약), 1부 3번(사실을 빠르게 읽게 함: 열기가 찼다는 사실을 소리로).

## 2026-11-03 · 배경음 기준 믹스(하스스톤식 크기 순서)

- **문제:** 사용자가 하스스톤처럼 배경음을 기준으로 효과음 크기를 맞춰 달라고 했습니다. 첫 믹스 표는 예전 배율을 옮긴 것이라 배경음과의 관계를 잰 적이 없었습니다.
- **측정:** 배경음 5곡을 효과음과 같은 K-가중으로 쟀습니다(`scripts/measure-bgm-loudness.cjs`). 곡 평균 -15.9~-17.1 LUFS(곡 사이 1.2dB라 따로 맞추지 않음), 기본 BGM 20%에서 약 -30.5 LUFS입니다. 일반 적중(0dB)의 가장 큰 100ms는 기본 효과음 10%에서 -25.8 LUFS로, 배경음보다 4.7dB 큽니다. 이 관계는 그대로 둡니다.
- **기준(배경음 대비, 효과음은 가장 큰 100ms·반복음은 평균):** 하스스톤 소리를 직접 잴 수는 없어, 하스스톤에서 들리는 순서를 따르는 일반적인 게임 믹스 관행으로 정했습니다.
  - 자주 나는 소리는 작게: 카드 호버 -4, 버튼 호버 -8, 화염구 비행 +2, 발사 +4(적중보다 작게, 하스스톤도 공격 준비보다 맞는 소리가 큼).
  - 결정·피드백은 배경음과 비슷하게(-2~+2): 카드 고름(도장) +2, 처치·발동·소환 0 안팎, 패배 +2.
  - 큰 사건만 확실히 위로: 축하 +6, 치명타 +14, 메테오 폭발 +18(예전 +21은 배경음을 완전히 덮어 8dB 이상 차이 나는 소리가 너무 많았음).
  - 카드 창이 열리면 배경음이 0.35배(-9dB)로 줄어들므로, 카드 호버·나눠 주기·도장·섞기·구매 거절은 줄어든 배경음 기준입니다.
- **바뀐 점(이전 → 이후, 배경음 대비):** 버튼 호버 -12.8 → -8.3, 카드 고름 -2.2 → +1.8, 처치 -5.8 → -0.3, 분노 경고 -9.8 → -4.3, 배경 소품 작은 소리 -15 안팎 → -9 안팎(메뉴·소품 소리는 배경음에 묻혀 거의 안 들렸음). 발사 +9.7 → +3.7, 메테오 폭발 +20.7 → +18.2, 치명타 +15.2 → +13.7, 충전 반복음 -1.8 → -4.3.
- **확인 필요:** 수치만으로 정한 1차 값입니다. 발사음을 적중보다 작게 줄인 것은 손맛에 영향이 커서, 믹싱 페이지에서 배경음과 함께 듣고 조정합니다. 하스스톤을 녹음해 오면(음악만·효과음만 따로) 같은 방식으로 재서 기준을 바꿀 수 있습니다.
- **관련 원칙:** 1부 2장(사건 규모별 반응 강약).

## 2026-11-03 · 효과음 믹싱 구조(믹스 표 + Web Audio)

- **문제:** 치명타 소리를 3배(배율 2.0 → 6.0)로 키우자 사용자가 "하나 바꿀 때마다 다른 소리와 균형이 무너진다"고 했습니다. 원인은 세 가지였습니다.
  1. 볼륨 배율(0.32~8.0)이 코드 곳곳에 흩어져 있어 소리 사이 관계가 어디에도 적혀 있지 않았습니다.
  2. HTML 오디오 볼륨은 1이 상한이라 효과음 슬라이더를 올리면 큰 소리부터 잘렸습니다. 슬라이더 20%에서 치명타(6.0 × 0.2)와 메테오 폭발(8.0 × 0.2)이 둘 다 1로 잘려 같은 크기가 됐습니다. 기본값끼리만 비교한 테스트는 이를 잡지 못했습니다.
  3. 파일마다 원래 음량이 달라(생성처·시기가 다름) 그 차이를 배율로 보정하고 있었습니다. 같은 소리의 변형끼리도 최대 4.5dB(카드 돌리기 1·2번) 차이가 났습니다.
- **결정:**
  - 파일 음량을 잽니다(`scripts/measure-sfx-loudness.cjs` → `src/scripts/sfx-loudness.js`). 귀 감도를 흉내 낸 K-가중(BS.1770)을 걸고, 짧은 소리는 가장 큰 100ms 구간, 반복음은 전체 평균을 씁니다. 표준 LUFS의 400ms 창은 0.1~0.5초짜리 효과음에서 무음까지 섞여 너무 작게 재서 쓰지 않았습니다. 파일을 바꾸고 다시 재지 않으면 테스트가 실패합니다.
  - 믹스 표(`src/scripts/sound-mixer.js`의 `SFX_MIX`) 한 곳에 소리마다 '들리는 크기'를 dB로 적습니다. 일반 적중이 0dB이고, 무리(전투·메테오·보상·UI·알림·소품)별로 한꺼번에 조절할 수 있습니다. 소리 하나를 바꿀 때는 그 칸만 고칩니다.
  - 첫 표는 바꾸기 직전에 들리던 크기를 그대로 옮겼습니다(슬라이더 10%에서는 잘리는 소리가 없어, 그때 크기를 사용자가 확인한 균형으로 봄). 한 파일짜리 소리는 예전과 0.5dB 안으로 같고, 변형 묶음만 서로 같은 크기로 맞춰졌습니다.
  - Web Audio로 재생해 1을 넘는 크기도 자르지 않습니다. 그래서 슬라이더 위치와 관계없이 표의 비율이 유지됩니다. 마지막 단 리미터(-2dB)가 겹침으로 찢어지는 것을 막습니다. 반복음은 켜고 끌 때 30ms로 미끄러지게 해 딸깍 소리를 없앴습니다.
  - Electron(file: 주소)과 웹 모두 35개 파일이 Web Audio로 로드되는 것을 확인했고, 스모크 테스트가 매번 확인합니다. Web Audio를 못 쓰거나 파일을 못 읽으면 그 파일만 예전처럼 HTML 오디오로 냅니다(1에서 잘림).
  - 슬라이더와 저장값의 의미는 바꾸지 않았습니다(기본 효과음 10%에서 들리는 크기는 그대로).
- **믹싱 페이지(같은 날):** `previews/sound-mixer.html`(게임 서버에서 `/previews/sound-mixer.html`). 게임과 같은 믹서·표로 소리를 내고, 소리별·무리별 dB를 슬라이더로 바꾸며, 게임에서 겹치는 순서를 흉내 낸 장면(전투 연사·메테오·처치·보상·카드·메뉴·배경 소품)과 배경음을 함께 들을 수 있습니다. 바꾼 값은 그 브라우저에만 저장되고, 에이전트가 `readMix()`로 읽어 `SFX_MIX`에 옮깁니다(1부 7번과 같은 방식: 화면에서 고르고 상태를 직접 읽음). 페이지가 게임과 같은 파일 목록을 쓰도록 효과음 파일 목록도 `game.js`에서 `sound-mixer.js`의 `SFX_FILES`로 옮겼습니다.
- **남은 것:** 큰 사건 때 다른 소리를 잠깐 낮추는 덕킹(무리별 GainNode 자리는 만들어 둠).
- **관련 원칙:** 1부 2장(사건 규모별 반응 강약), 1부 5번(구형 볼륨 배율 잔재 제거, 테스트가 감시).

## 2026-11-02 · Steam 업적 연동(배경 소품 큰 반응)

- **문제:** 배경 소품 보상 후보로 Steam 업적이 골라졌지만 Steam 연동 코드가 전혀 없었습니다. 앱 ID도 아직 발급 전입니다.
- **결정:**
  - 라이브러리는 `steamworks.js`(MIT, Rust/N-API). Windows용 `steam_api64.dll`과 미리 빌드된 모듈이 함께 들어 있어 Electron 버전이 바뀌어도 다시 빌드할 필요가 없습니다. `greenworks`는 2022년 이후 멈췄고 Electron 버전마다 재빌드가 필요하며, `steamworks-ffi-node`는 Steamworks SDK DLL을 따로 받아 넣어야 해서 뺐습니다. 위험: 마지막 배포가 2024-08(0.4.0)이라 SDK가 최신이 아닙니다. 업적 API는 오래 안정적이라 지금은 충분하고, 문제가 생기면 같은 자리(`electron/steam.cjs`)에서 바꿉니다. 네이티브 파일은 asar 안에서 읽히지 않아 `asarUnpack`으로 풉니다.
  - 앱 ID는 실행 인자 `--steam-appid=` → Steam이 넣어 주는 `SteamAppId` 환경 변수 → `STEAM_APP_ID` 상수 순서로 정하고, **없으면 Steam을 아예 건드리지 않습니다.** `steam_appid.txt`에 480을 넣어 두는 흔한 방식은 쓰지 않았습니다. 개발 실행마다 친구 목록에 'Spacewar 플레이 중'이 뜨고, 480에는 우리 업적 id가 없어 해제 확인도 안 되기 때문입니다. 480은 `npx electron . --steam-appid=480`으로 연결만 시험할 때 씁니다.
  - Steam 미실행·라이브러리 오류·브라우저 실행에서는 아무 일도 하지 않습니다. 업적 통로는 렌더러 → `desktopSteam.unlockAchievement`(preload) → IPC `steam:unlock-achievement` → 메인 프로세스이고, 메인은 목록에 있는 id만 해제합니다. 해제 실패(통계 수신 전)는 2초 간격으로 5번까지 다시 시도합니다. Steam 오버레이(업적 알림 팝업)는 연결에 성공했을 때만 켭니다(GPU 관련 스위치가 붙어 화면 렌더링이 달라질 수 있어서).
  - 업적 목록·이름은 체크 표시 페이지로 골랐습니다. 원본은 `src/scripts/steam-achievements.js`(Steamworks 등록 시 이 파일의 id·이름·설명을 옮겨 적음). 소품 7종(수정 깨는 자·꺼지지 않는 불·탈선·옥좌의 불·잿빛 깃발·공허의 선율·누가 거기 있니?) + 모두 찾기 1종(호기심 많은 마법사)이며, 모두 찾기는 세이브가 아니라 Steam의 해제 상태로 판정합니다.
  - **숨김 업적으로 등록합니다.** 업적 목록에 '수정을 5번 두드리기'가 보이면 우연히 발견하는 재미가 공략표로 바뀝니다(4장 1번).
  - 보상은 업적뿐이고 전투 수치·골드는 그대로입니다.
- **남은 것:** 앱 ID 발급 후 `STEAM_APP_ID` 입력, Steamworks에 업적 등록(아이콘 포함), 실제 Steam에서 해제·오버레이 팝업 확인. 실행 파일을 Steam 밖에서 켰을 때 Steam으로 다시 띄우는 `restartAppIfNecessary`는 앱 ID가 생긴 뒤 넣을지 정합니다.
- **관련 원칙:** 4장 1번(정답 표시 금지 → 숨김 업적), 1부 7번(후보는 체크 표시로).

## 2026-11-02 · 배경 소품 상호작용 시범(폐광 수정·성채 화로)

- **문제:** 배경이 테마마다 정지 원화 한 장이라 죽어 보였습니다. 사용자 제안은 하스스톤처럼 배경 물체를 계속 누르면 반응하는 것입니다(보석이 깨지고, 고양이가 화냄). 2026-10-04에 캔버스로 그린 조명·움직이는 소품·광원 클릭 반응을 넣었다가 요청에 따라 전부 뺀 이력이 있습니다(사유 기록 없음, `docs/2026-10-04-arena-environments.md`). 당시에는 원화 위에 수정·톱니·불꽃을 **따로 그려** 얹었습니다.
- **결정:** 움직이는 소품은 **원화에서 잘라 낸 조각만** 씁니다(`scripts/build-arena-props.py`). 캔버스로 새로 그리는 것은 금·파편·불티·빛 같은 반응 효과뿐입니다. 먼저 두 개만 시범으로 넣었습니다.
  - 폐광 수정: 누를 때마다 흔들리고 금이 가며, 음이 조금씩 올라갑니다. 처음에는 금을 검은 잉크선으로 그었는데 '검은 실을 붙인 것 같다'는 의견이 나왔습니다(레퍼런스 확인 없이 짐작으로 그린 결과). 만화풍 얼음·깨진 유리·종이 수정 레퍼런스를 보고, **맞은 지점에서 뻗어 나가는 하얀 갈라짐** + 한쪽의 옅은 푸른 그늘(면이 어긋난 느낌)로 바꿨습니다. 5번째에 원화 조각이 파편으로 흩어집니다. 다음 스테이지에서 다시 자랍니다. 빈자리는 주변 질감으로 메우면 뒤에 있던 나무 기둥·동굴 벽이 끼어들거나 흐려져서, 어두운 '오려 낸 구멍'과 깨진 밑동으로 남깁니다.
  - 성채 화로: 불꽃 조각이 늘 살짝 일렁입니다(원래 크기 이상으로만 늘려 원화 속 정지 불꽃이 비치지 않게 함). 누르면 치솟았다가 7초간 크게 탑니다. 큰 화로 4개를 모두 키우면 옥좌가 빛납니다.
