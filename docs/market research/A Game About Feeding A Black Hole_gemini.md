# 그런데 부정 리뷰가 훨씬 흥미롭습니다

부정 리뷰들을 보면 사실상 **4개의 문제가 반복적으로 등장합니다.**

### 1. 가장 큰 불만: 업그레이드가 너무 선형적이다

이건 압도적으로 반복됩니다.

겉으로는 Skill Tree처럼 보이지만 실제로는 가격 때문에

**A → B → C → D → E**

순서대로 살 수밖에 없습니다.

그래서 플레이어 입장에서는

> "어떤 업그레이드를 살까?"

가 아니라

> "다음 업그레이드를 살 돈이 모였나?"

가 됩니다.

한 리뷰는 아예 **스킬트리를 'Unlock Next Upgrade 버튼 하나로 바꿔도 된다'**고 비판합니다. 다른 리뷰들도 "choices rarely feel meaningful", "exact same order as everyone else"라고 같은 문제를 지적합니다.

이건 당신이 증분게임을 만든다면 **가장 참고할 만한 지점**이라고 봅니다.

---

### 2. 성장하는데 강해진 느낌이 사라진다

이것도 상당히 중요한 비판입니다.

숫자는 커지는데 동시에

- 블랙홀이 커지고
- 적/오브젝트 HP가 커지고
- 새로운 자원 단계가 나오면서

기존의 강함이 상쇄됩니다.

즉,

**100 Damage → 적 HP 1,000**

에서

**10,000 Damage → 적 HP 100,000**

이 되어 버립니다.

수학적으로 100배 강해졌지만 **체감은 똑같습니다.**

한 상세 리뷰는 이걸 정확히 지적하면서 "technically becoming stronger"인데도 홀 크기가 커지면서 성장의 임팩트가 줄어든다고 평가합니다. 또한 새로운 메커니즘이 등장한 뒤 제대로 활용하기도 전에 다음 단계가 등장해서 기존 시스템을 무의미하게 만든다는 지적도 있습니다.

증분게임에서 굉장히 위험한 디자인입니다.

### 성장 ≠ 숫자 증가

여기서 플레이어가 원하는 것은

**"예전에 힘들었던 것을 지금은 말도 안 되게 박살 내는 경험"**

입니다.

---

### 3. "Big numbers go BRRR" 순간이 부족하다

위 문제와 연결됩니다.

증분게임 플레이어들이 기대하는 순간은 보통

> 처음: 돌 하나 부수는 데 10초
> 중반: 돌 100개가 한 번에 터짐
> 후반: 화면 전체가 폭발
> 극후반: 초당 행성 수백만 개 삭제

같은 **power fantasy**입니다.

그런데 이 게임은 밸런스를 계속 유지하려다 보니 이 폭주 구간을 상당히 억제했다는 평가가 있습니다.

실제 부정 리뷰 중에는 아예

**"'Big numbers go brrr' never really happens."**

라고 요약한 리뷰가 있습니다.

흥미로운 것은 이게 장점과 정확히 충돌한다는 것입니다.

**긍정:** 밸런스가 좋다. Grind가 없다.
**부정:** 너무 밸런스가 잡혀 있어서 미쳐 날뛰는 순간이 없다.

증분게임에서는 **밸런스를 일부러 무너뜨려주는 순간**도 보상이 될 수 있다는 의미입니다.

---

### 4. 반복 플레이 / 전략 깊이가 부족하다

부정 리뷰에서는

**move mouse → 돈 획득 → upgrade → move mouse → upgrade**

구조가 너무 오래 유지된다는 지적도 반복됩니다. view0

특히 증분게임 팬들은 다음 요소를 기대하는 경향이 있습니다.

**Build / Synergy / Prestige / Automation / Meta progression**

그런데 이 게임은 플레이어 선택이 제한적이라

**"내가 만든 빌드"**

라는 느낌이 약합니다.

그래서 초반에는 재미있지만 시간이 지나면 **linear / repetitive / boring**이라는 평가가 등장합니다. 리뷰 분석 자료에서도 Linear Upgrade Path가 가장 강한 부정 테마이고, Gameplay Repetition이 그 다음 주요 불만으로 잡힙니다.

# 재미있는 역설

이 게임의 가장 큰 장점과 가장 큰 단점이 사실 **같은 설계에서 나옵니다.**

**개발자가 플레이어 경험을 강하게 통제했습니다.**

그래서:

**장점**

> 항상 적절한 속도로 성장한다.
> 막히지 않는다.
> Grind가 없다.
> 편안하다.
> 업그레이드가 계속 나온다.

하지만 동시에:

**단점**

> 선택할 필요가 없다.
> 빌드를 만들 필요가 없다.
> 최적화할 필요가 없다.
> 실패할 수도 없다.
> 플레이어마다 플레이가 거의 같다.

즉,

### Curated Progression ↔ Player Agency

사이의 트레이드오프가 굉장히 잘 보이는 게임입니다.

# 당신이 만드는 증분게임에 가져올 핵심

저라면 이 게임에서 **긍정 요소는 거의 그대로 가져오고, 부정 요소만 반대로 설계**하겠습니다.

**유지할 것**

`짧은 Run → 자원 획득 → 즉시 Upgrade → 즉시 체감`

그리고 업그레이드 하나를 샀을 때

**숫자뿐 아니라 화면이 달라지게 하는 것.**

예를 들어

> Damage +20%

보다

> 공격이 관통한다
> 적이 폭발한다
> 폭발한 적이 다른 적을 공격한다
> 적이 죽으면 새 적이 생성된다

같은 변화입니다.

반대로 가장 피해야 할 것은

**가짜 선택지**입니다.

```
      A
     / \
    B   C
     \ /
      D
```

처럼 생겼는데 가격 때문에 항상

`A → B → C → D`

순서라면 Tree를 만들 이유가 없습니다.

차라리

```
       POWER
      /     \
 EXPLOSION  SPEED
    |         |
 CHAIN      MULTI
    \         /
     SYNERGY
```

처럼 **어느 쪽을 먼저 가느냐에 따라 실제 플레이가 달라지는 구조**가 낫습니다.

그리고 특히 중요하게 생각되는 한 가지가 있습니다.

### 플레이어가 과거의 자신을 압도하게 해주세요.

새 Tier가 나왔다고 이전 Tier를 바로 없애버리지 말고,

처음에는 힘들게 잡던 대상이

**10초 → 1초 → 한방 → 범위 공격 → 화면 전체 삭제 → 자동 삭제**

되는 과정을 보여주는 겁니다.

이게 증분게임에서 숫자가 커지는 것보다 훨씬 강한 **성장의 시각화**가 됩니다.

## 한 문장으로 리뷰 전체를 압축하면

> **"성장 속도와 손맛은 훌륭하지만, 개발자가 플레이어의 성장 경로를 너무 잘 통제해서 '내가 이 시스템을 공략하고 있다'는 느낌이 부족하다."**

그래서 당신 게임에서는 **이 게임의 빠른 피드백과 시각적 만족감 + 플레이어가 시스템을 깨뜨릴 수 있는 빌드/시너지**를 결합하는 방향이 꽤 강할 것 같습니다.
